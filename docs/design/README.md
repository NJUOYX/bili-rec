# bili-rec 设计文档

本目录是 bili-rec 项目的**唯一设计事实来源（Single Source of Truth）**。所有开发工作都基于本目录中的设计文档进行；任何功能演进都必须**先修改设计文档**，再据此实现代码。

## 文档清单

| 文档 | 说明 | 状态 |
|---|---|---|
| [backend-design.md](./backend-design.md) | 后端详细设计（架构、模块、API、测试、CI/CD） | **进行中（当前阶段）** |
| [frontend-design.md](./frontend-design.md) | 前端详细设计 | 延后（占位） |
| [../../blrec后端功能清单.md](../../blrec后端功能清单.md) | 功能范围决策记录（源自对 blrec 的调研） | 已冻结（作为需求基线） |

## 文档治理规则

1. **设计先行**：先改文档、评审通过，再写代码。代码实现必须与设计文档一致；发现不一致时，要么改代码，要么走变更流程改文档。
2. **版本控制**：本目录随 Git 版本控制。每个文档头部维护「文档信息」表（版本号 + 状态 + 最近更新）。
3. **变更记录**：每个文档底部维护「变更记录（Changelog）」表，记录版本、日期、变更摘要。
4. **语义化版本**：文档版本采用 `MAJOR.MINOR`：
   - `MAJOR`：架构级/不兼容的设计变更；
   - `MINOR`：新增模块、接口、字段等增量变更。
5. **评审**：设计变更通过 Pull Request 提交，至少一名评审者批准后合并。PR 描述需说明变更动机与影响面。
6. **需求基线**：功能范围以 `blrec后端功能清单.md` 的「最终功能范围（决策记录）」为准；范围调整需同步更新该文件与本设计文档。

## 阶段规划

- **阶段一（当前）**：后端。按 `backend-design.md` 实现录制核心、任务管理、Web API、后处理、测试与 CI/CD。
- **阶段二**：前端。届时启动 `frontend-design.md`，与后端 API 契约对齐。
